# بازتولید آزمون نامزد ارتقا پس از `.5`

این راهنما برای توسعه‌دهنده و **صرفاً محیط کاملاً دورریختنی و مستقل** است؛ روی هاست عملیاتی، روی کپی متصل به سرویس‌های واقعی یا روی دیتابیس دارای اطلاعات واقعی اجرا نشود. شرط نام `hhx_test_*` و `localhost` به‌تنهایی ثابت نمی‌کند یک سرور MySQL، آزمایشی و جدا از سرور واقعی است. cron، شبکهٔ ارائه‌دهندگان، پیام‌رسانی و سایر خروجی‌های واقعی را غیرفعال کنید. هیچ کلید یا اطلاعات شخصی در نمونه‌ها لازم نیست.

## بازسازی ZIP و بررسی آفلاین

از ریشهٔ مخزن، پس از اطمینان از وجود commitهای پین‌شدهٔ `3547693` و `543b0d6` در Git:

```bash
python3 scripts/build_update_candidate.py
python3 tests/upgrade_candidate_overlay_smoke.py
(cd release-files/after-v2026.11.07.5-rc1 && sha256sum -c SHA256SUMS.txt)
```

سازنده، کد اجرایی را از اشیای Git می‌خواند نه از فایل‌های تغییرکردهٔ محلی. فشرده‌سازی در نسخه‌های متفاوت Python/zlib ممکن است بایت و هش ZIP متفاوت تولید کند؛ فهرست بایت‌های اجرایی و بررسی CRC را نیز بررسی کنید. تست دوم نصب کامل قدیمی و بسته‌های به‌روزرسانی را در پوشهٔ موقت بازسازی می‌کند، ۸۰ فایل مبنا، ۲۶ تغییر، ۹۶ فایل مقصد، فهرست‌های هش، محتوای ZIP و حفظ فایل‌های ساختگی را بررسی می‌کند. این فقط شبیه‌سازی مبنای مخزن است، نه کپی هاست کاربر.

## آزمون دو مرحله‌ای دیتابیس

1. یک ماشین/کانتینر مستقل و بدون دادهٔ واقعی با PHP دارای `PDO MySQL` و `mbstring` و یک MySQL محلی راه بیندازید. یک دیتابیس **خالی و دورریختنی** با نامی مانند `hhx_test_upgrade_demo` و دسترسی محدود ایجاد کنید. نام، میزبان و مسیر Unix socket باید واقعاً مربوط به همان نمونهٔ جداگانه باشند.
2. از ریشهٔ مخزن، یک پوشهٔ جدید خارج از مخزن برای نصب ساختگی بسازید. نمونهٔ زیر خودِ پوشهٔ `site` را توسط آزمون می‌سازد؛ از مسیر قبلی یا واقعی استفاده نکنید:

   ```bash
   ROOT="$PWD"
   PARENT="$(mktemp -d)"
   STAGE="$PARENT/site"
   python3 tests/upgrade_candidate_overlay_smoke.py --baseline-only --stage "$STAGE"
   ```

   این حالت کد قدیم و دو fixture آزمایشی را نگه می‌دارد. فایل `config/config.local.php` در آن صرفاً نشانگر ساختگی است؛ آن را با پیکربندی **فقط همان دیتابیس موقت** جایگزین کنید. کلید `advertising_payments.experimental_sandbox` باید غایب یا بولی `false` باشد. مقادیر واقعی و کلیدهای واقعی به این محیط وارد نکنید.
3. با PHP محلی، مسیر مطلق پیکربندی ساختگی و یک رمز کاملاً ساختگی حداقل ۱۲ نویسه، متغیرهای زیر را تنظیم کنید؛ سپس fixture را اجرا کنید. رمز و تنظیمات واقعی را در فرمان، مستندات یا گفتگو قرار ندهید.

   ```bash
   export HHX_ALLOW_TEST_FIXTURES=1
   export HHX_TEST_CONFIG="$STAGE/config/config.local.php"
   export HHX_TEST_PASSWORD='synthetic-only-password'
   php "$STAGE/tests/setup_article_url_fixture.php"
   php "$STAGE/tests/upgrade_candidate_database_smoke.php" baseline
   ```

   فاز `baseline` با کد قدیم، مایگریشن‌های هدفمند `006` و `007` را اجرا می‌کند و محتوای منتشرشده و تنظیمات ساختگی می‌سازد؛ `003` عمداً ثبت نمی‌شود. fixture داده‌ها را commit می‌کند و دیتابیس باید خالی باشد.
4. پیش از استخراج، فهرست مبنا را از **ریشهٔ همان کپی آزمایشی** بررسی کنید. سپس دقیقاً ZIP تولیدشده را روی همان پوشه استخراج و مانیفست داخل آن را بررسی کنید:

   ```bash
   (cd "$STAGE" && sha256sum -c "$ROOT/release-files/after-v2026.11.07.5-rc1/BASELINE-SHA256.txt")
   (cd "$STAGE" && unzip -o "$ROOT/release-files/after-v2026.11.07.5-rc1/hamihub-update-after-v2026.11.07.5-rc1.zip")
   (cd "$STAGE" && sha256sum -c UPGRADE-RC-MANIFEST.txt)
   php "$STAGE/tests/upgrade_candidate_database_smoke.php" upgraded
   ```

   فاز دوم باید توقف اجرای عمومی هنگام غیبت `003`، اجرای هدفمند `008` تا `010`، اجرای دوباره بدون تغییر، حفظ محتوای قدیم و خاموش‌بودن سندباکس را بررسی کند. خطا را دور نزنید. این فرآیند عمداً فقط روی دادهٔ ساختگی است.
5. برای تست برخورد رسید، یک دیتابیس خالی و مستقل دیگر از همان نوع بسازید، `setup_article_url_fixture.php` و سپس `tests/advertising_receipt_migration_smoke.php` را از **کپی به‌روزشده** با پیکربندی آن اجرا کنید. آن تست تعارض ساختگی می‌سازد و فقط در fixture یک ثبت را ابطال می‌کند؛ این کار دستور رفع تعارض حسابداری واقعی نیست.

تست‌های HTTP و هم‌زمانی موجود در `tests/` نیاز به fixtureهای محافظت‌شده و دیتابیس‌های ساختگی جداگانه دارند؛ مستندات `ADVERTISING_FINANCE_FA.md` را ببینید. سرورهای موقت را پس از آزمون متوقف کنید. هیچ نتیجه‌ای از این آزمون‌ها، بازیابی بکاپ، بارگذاری تصویر، امنیت، کارکرد روی هاست واقعی یا رفتار درگاه واقعی را به‌تنهایی تأیید نمی‌کند.
